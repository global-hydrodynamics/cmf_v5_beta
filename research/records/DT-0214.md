## Objective and scope

Use named-column CSV as the standard output for the five maintained CaMa-Flood v5 allocation-result tables: GRDC, the three separate GRanD categories, and MLIT level gauges. Update their producers, active consumers, Mekong sample products, metadata and user guidance without changing allocation algorithms, source observations, or historical v4 implementations.

## Survey report

The three maintained Python allocation programs are the direct producers. They previously wrote whitespace-aligned tables; the shared v5 wrappers invoke these programs and leave their products at the map root. GRDC allocation is also read by the advanced upstream-basin example and Tutorial 11's gauge-allocation workflow. The legacy Fortran programs and `map/src/src_param/` wrappers are historical v4 references and were left unchanged. The five Mekong legacy tables contained 175 GRDC rows, 2 GRanD error rows, 244 GRanD river rows, 127 GRanD small-category rows, and no MLIT rows. The empty MLIT product is a supported header-only case.

The existing allocator contracts define column order, numeric formatting precision, record order, and numeric sentinel/classification codes. GRanD names occupy fixed-width fields in the legacy output; the new CSV contract stores them as strings and relies on standard CSV quoting. The allocation category names are preserved as produced; `GRanD_small` remains an area-rule category, not an independently verified physical class.

## Work report

- `allocate_flow_gauge.py`, `allocate_dam.py`, and `allocate_level_gauge.py` now write `GRDC_alloc.csv`, `GRanD_{river,small,error}.csv`, and `MLIT_levelgauge.csv` directly with the schemas documented in `variable_table/map_metadata_spec.md`.
- Added `analysis_select_grdc_allocation.py` for named-column selection of the same valid GRDC row with the greatest `area_CaMa`; maintained shared and map-local upstream-basin wrappers and Tutorial 11's reader now use the CSV output.
- Replaced the five Mekong sample TXT outputs with CSV. All parsed values, identifiers, ordering, and sentinel/classification fields matched the original data; MLIT remains a valid header-only file.
- Updated the map variable registry, authoritative schema documentation, allocation workflow guides, migration documentation, and directly affected tests/benchmark comparison. No legacy v4 source, external map, or source observation inventory was modified.

## Validation

See [VR-0260](validation_runs/VR-0260.md). Four focused suites passed: **20 tests and 34 subtests**. The tests exercise direct producer outputs against preserved Fortran reference results, wrapper behavior, NetCDF allocation readers, and analysis consumers. An independent parsed-record comparison matched all five Mekong CSV outputs against the original TXT from the starting revision, including all 548 non-empty records and zero MLIT records. Map registry validation, Python syntax parsing, Shell syntax checks, and the scoped diff review passed.

## Compatibility and remaining limits

The maintained v5 allocation readers and wrappers now use CSV directly; no general TXT fallback or conversion tool was added. Historical v4 programs remain TXT-based. External datasets with only legacy allocation outputs were not modified and require an explicit conversion before use by CSV-only v5 consumers. The checked regressions establish tested behavioral parity and format preservation, not independent scientific validation of each station or dam allocation. The repository-wide research validator still reports unrelated pre-existing record errors; no unrelated records were changed to suppress them.

## Knowledge-gap review

The required checklist found no material new scientific or architectural question caused by this serialization change. Existing uncertain sentinel semantics and external-map legacy dependencies are preserved and documented in the allocation schema/migration material; this task did not reinterpret them.
