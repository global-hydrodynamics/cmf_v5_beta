## Objective and scope

Keep `s02-python_setup.sh` as the only setup entry point. Try the root standard requirements first, validate dependency consistency and principal imports, and make one resolver-based attempt using `config/python/requirements_2024.txt` if installation or validation fails. Preserve Python discovery, interactive confirmation, editable CMF Colormaps, existing `.venv`, and activation instructions. The 2022 profile remains excluded.

## Change and enabled capability

The setup now installs standard requirements and CMF Colormaps in a single pip resolution, prefers a Rasterio wheel, then runs `pip check`, imports required scientific/visualization packages, and verifies `shade_rainbow`. A failed install or check triggers exactly one eager resolver run against the complete 2024 profile, followed by the same validation. Success identifies the selected profile and Python version. Failures retain pip/import diagnostics. No environment recreation or unrelated package removal is performed. README and Python setup guidance describe the fallback and its platform limits.

## Validation

See VR-0262. A clean temporary checkout passed the standard path under a test-only NumPy 1.26.4 constraint. A disposable existing environment seeded from the 2024 profile and then upgraded to incompatible NumPy 2.5.5 passed through the fallback: NumPy was downgraded to 1.26.4, `pip check` passed, all required imports passed, and the colormap check passed. A local unavailable-index test exercised both-install-failure reporting. Interactive decline and no-TTY diagnosis preserved their behavior. The repository `.venv` remained unchanged.

An additional real resolution against the current floating root requirements selected NumPy 2.5.5 and installed netCDF4 1.7.5.1.post1; import validation detected their ABI mismatch and triggered the fallback. The fallback then correctly reported `panel-material-ui 0.17.0` left by the standard install as incompatible with pinned Panel 1.5.5/Bokeh 3.6.2. The script did not remove this unrelated package. This is a known limitation when the standard install leaves extra packages that conflict with the historical profile; the diagnostic is explicit, and the existing environment remains intact.

## Scientific and compatibility impact

No scientific algorithms, model code, or input data changed. This changes only repository-local Python dependency setup. The 2024 pins have focused macOS arm64 / CPython 3.12 evidence, not a guarantee across OS, architecture, package index, or historical Python versions. The isolated checks do not constitute OS-level beta-user validation.

## Knowledge-gap review

No new scientific question was introduced. A compatibility limitation is documented: pip does not remove unrelated distributions that remain after switching profiles, and `pip check` can reject those leftovers. Setup reports the package conflict and stops rather than deleting user-installed packages or recreating `.venv`. Additional OS/CPU validation remains open before making broader support claims.
