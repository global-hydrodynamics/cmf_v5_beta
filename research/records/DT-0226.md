## Area and prior constraint

Development infrastructure and visualization launch. The prior setup validated package presence rather than native imports, was scoped to macOS, and the normal WSL launcher disabled automatic setup. Historical dependency profiles already exist for 2024 and 2022; full 2022 GUI compatibility is assigned to a separate Cloud run.

## Change and enabled capability

The shared launcher now validates package consistency (`pip check`), compiled imports, and Panel/Bokeh API construction, with a synthetic-map `Explorer` initialization for candidate environments. When setup is authorized it attempts standard, 2024, then 2022 requirements in separate platform/profile environments. It keeps existing environments intact, and offers the hidden `--test-setup-profile 2024` path for safe fallback verification. WSL profile environments are under the Linux user's cache; `--no-setup` remains available explicitly. Added minimal Explorer-specific profile requirement files and updated launch documentation.

## Scientific and compatibility impact

Scientific calculations, map readers, visualization settings, and source datasets were not changed. The new 2024 macOS arm64 profile uses netCDF4 1.6.5 on Python 3.10–3.12 because 1.7.2 has no wheel for the supported older macOS range; other target platforms retain the historical 1.7.2 profile pin.

Local macOS arm64 / 13.7.8 / CPython 3.12.3 completed a separate 2024 environment installation, `pip check`, compiled imports, synthetic-map `Explorer` initialization, and a loopback HTTP 200 response. The repository Mekong map has `params.nml`, whereas this checked-out Explorer still expects `params.txt`, so its default-map launch was not validated. Native Windows and WSL runtime verification, and the full 2022 GUI verification, remain outstanding.

## Knowledge-gap review

Checklist completed. No new scientific-definition gap was introduced. Platform package-wheel availability can change and requires future revalidation. Native Windows/WSL behavior and full 2022 GUI compatibility require execution on their target hosts; these are documented validation limits, not claims of support.
