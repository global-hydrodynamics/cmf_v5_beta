# DT-0210 — Migrate diminfo metadata to native Fortran Namelist

- **Branch:** `feature/package-builder`
- **Starting commit:** `b530a2e69529260d386f9621778a4cc09cdd56dc`
- **Status:** Implemented; focused checks passed. NetCDF-dependent checks were unavailable, and the broader mixed test run exposed unrelated failures. Changes remain uncommitted.

## Objective and prior constraint

Replace the maintained v5 positional `diminfo_<ROFFTAG>.txt` interface with one native Fortran Namelist file while preserving each of its eleven fields. The legacy text form was positional and required separate format-specific parsing; current v5 model initialization and per-input mapping both needed a consistent named-field interface.

## Implementation

Added `DimInfo`, a shared `f90nml`-based reader/writer, validation, and an explicit, safe `migrate_diminfo.py` utility. The normal Python producer and regional default workflow now write `.nml`; converters, CTL generation, map tools, model run configurations, and selected tutorial references use the new suffix. `CDIMINFO` and the independent `diminfo_file` reader consume the native `&DIMINFO` group without changing their separate path semantics. `INPMAT_FILE` remains descriptive and does not override `CINPMAT` or the explicitly configured per-input matrix path.

The schema has exactly `NX`, `NY`, `NLFP`, `NXIN`, `NYIN`, `INPN`, `INPMAT_FILE`, `WEST`, `EAST`, `NORTH`, and `SOUTH`. The geographic bounds remain model-grid edges; runoff-grid bounds and resolution were not added.

## Local map migration

Found 12 positional descriptors under `map/` and produced 12 sibling Namelists. Shared Python readers compared all eleven parsed values in every pair. Eight TXT files were removed after the current v5 consumers had been changed and checked: the two Rhine descriptors and six Mekong root/Binary sample descriptors. Four TXT files remain alongside verified NML files for ignored `glb_15min` and `TE-Japan_01min` Binary map-local scripts that still generate/read the legacy binary workflow. Existing ignore/tracking policy was preserved.

One preserved source inconsistency remains visible: `map/mekong_15min/binary/diminfo_ERA5land_global.nml` names `inpmat_ERA5land_global.nc`, while that NC product is in the map root rather than in `binary/`. The original field was preserved exactly; resolving the stale/misplaced metadata requires maintainer confirmation. No matrix was changed.

## Scientific and compatibility impact

No scientific calculation, matrix value, array order, grid coordinate, or model parameterization changed. The descriptor format and maintained filenames changed. Historical source and explicitly legacy workflows remain separate; no TXT fallback was introduced into maintained readers. The four old local descriptors retained for Binary legacy scripts must not be mistaken for files consumed by the new v5 Namelist readers.

## Validation

See [VR-0254](validation_runs/VR-0254.md). Thirty-two focused Python metadata/CTL and Mekong integration tests passed; the Fortran input-mapping harness passed 22 double-precision and 22 single-precision cases; `cmf_ctrl_nmlist_mod.F90` compiled; and all 12 local TXT/NML pairs compared exactly before removal. Mekong sample validation, changed Shell syntax checks, and `git diff --check` passed. The input-slice test could not start because `netCDF4` is absent in the active interpreter. A broader mixed test run reported six failures in other map/legacy cases and seven optional skips; these were not established as regressions from the descriptor migration. The repository research-record validator reports 17 unrelated errors and still needs separate cleanup.

## Knowledge-gap review

One data-quality issue remains: the binary-subdirectory ERA5 descriptor's paired filename does not match a file in that directory. It is non-blocking for the format migration because the data value was preserved rather than guessed. Human review is needed before changing that field or relocating its paired matrix. The legacy workflows that still use TXT are listed above; transition of those ignored map-local scripts is outside this implementation.
