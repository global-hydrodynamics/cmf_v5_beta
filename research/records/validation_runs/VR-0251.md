## Task metadata and impact

- **Area:** Map preprocessing interfaces, documentation, tests, and development records.
- **Prior constraint:** River inspection commands/examples were split into a dedicated Shell family and map-local copies; CTL generation was still exposed from the regionalization family. See the pre-task `script_analysis/` tree and `script_region/s02-write_ctl.sh`.
- **Change and enabled capability:** The generic commands and three-level examples now live beside map parameter workflows, while regionalization and format conversion retain separate responsibilities. Map-specific GRDC allocation remains available for robust station-cell selection.
- **Scientific and compatibility impact:** No scientific algorithm, model parameter, Python CLI, map product, or input data was changed. The wrapper output paths and GRDC eligibility/selection behavior were checked. A pre-existing NetCDF/Fortran subbasin result discrepancy was exposed and remains outside this task.

## Survey Report — Existing workflow organization

- The former shared and Mekong `script_analysis/` directories contained Shell entry points/examples that directly wrap Python programs already centralized in `map/tools/code/`. The separate shell family duplicated map-local copies and required a special code-link layout.
- River-point inspection, upstream-basin generation, and GRDC-selected catchment inspection are map-local inspection/preparation actions that can be grouped with the existing `script_params/` family without moving or renaming the Python calculation utilities.
- Regionalization (`script_region/`) remains a distinct workflow. GrADS CTL generation is format-conversion support and now belongs in `script_format_conv/` alongside its existing Python generator.
- Historical research records retain old directory names as evidence; current user-facing guides point to the maintained families.

## Work Report — Implementation

- Added shared `get_river_point_info.sh`, `calc_upbasin.sh`, Mekong-coordinate examples a01/a02, and `a03-advanced_calc_upbasin.sh` to `map/tools/script_params/`, with map-local copies in Mekong and Rhine.
- The GRDC example keeps the existing eligibility filters and first-row tie behavior, then uses the largest valid positive `area_CaMa` allocation and its primary cell. Its report and mask names remain `grdc_station_selection.txt`, `grdc_river_info.txt`, and `upbasin-<GRDC_ID>.nc`.
- Removed tracked `script_analysis/` wrappers/READMEs from shared tools and Mekong. Retained the Python implementation utilities. Removed the CTL wrapper from `script_region/` and map-local Mekong/Rhine `script_region/`; the maintained `s09-write_ctl.sh` in `script_format_conv/` remains the entry point.
- Updated shared, Mekong, Rhine, map-level, migration-status, and stage documentation; refreshed `map_variables.csv` script references and tests. The package/local ignored global-map directory was left untouched.
- No scientific algorithm, output naming contract, model source, or map input data was modified.
