## Approved scope and design

The maintainer supplied the complete implementation request: reuse the existing
map converter, add --reference-binary, remove only the subbsn-sample/subcol-sample
registry rows, add shared/Mekong s90 settings, generate and track two NetCDFs,
validate and document, then commit/normal push on the current approved branch.
Current branch and upstream matched; git fetch succeeded after the filesystem
sandbox required escalation. Connected GitHub searches found no open v5 Issue/PR.
The published main dashboard was read; its package-builder registration is absent,
while current branch records explicit prior maintainer assignments there. This
request is treated as bounded authorization on that existing branch; no main
registry publication, branch creation/switch, merge or force push was performed.

CSV remains the sole standard variable definition; Shell owns literal variant
names. Exact registered base filename references load all definition rows and
validate supported types, dimensions, complete unique record indices/counts and
unique output names before --variables filtering. Partial selection is allowed
but still requires complete input bytes. Each record retains its dtype/offset.
The former nextxy naming compatibility uses the reference filename when supplied;
nextxy_noedge retains nextx/nexty aliases. No-reference inference and the legacy
--variables fallback remain; companion records are validated for fallback too.

The existing writer is reused, with same-directory staging, read-back checks,
close then no-replace link publication or explicit-force atomic replacement.
Failure removes temporary output and preserves an old destination. The existing
one-layer profile path used rank-2 start/count buffers for a rank-3 variable;
using the registered dimension for rank selection fixes that directly related
layer case, now covered by a 1-layer fixture. No scientific arrays are changed.

The s90 copies are byte-identical Bash scripts. CWD selects the parent map;
--map-dir overrides and shared-template implicit use is rejected. Settings are
input.bin:reference.bin pairs; missing/size/registry errors remain in Python.
No prompts/overwrite without explicit force. Earlier completed variants are
retained if a later file fails. Original Binary files are untouched.

Only the two requested CSV rows were removed, with every retained byte (including
workflow_stage) identical to the original. Other sample rows stay intact. Sample
30,000/5,000 km² generation conditions are preserved in both conversion READMEs
and the existing s06 wrapper. The list and CTL/sample tests reflect that concrete
variants are no longer automatic registry candidates; standard CTL data/layout
assertions and sample network/category assertions remain.

Input-matrix conversion is documented only: a future separate
convert_inpmat_binary_to_netcdf.py should reuse CSV definitions but handle
NX,NY,INPN, mixed inpx/inpy/inpa blocks and diminfo input-grid metadata. No such
converter/wrapper, model run, Fortran, Explorer, river_map, COG, high-resolution
algorithm or package-builder change was made.

using positional arguments for optional --force fixed it. A fallback test using

legacy nextx partial fallback is separately tested. Initial sample/CTL assertions

reported, not fixed. Existing 12 research local-link errors were recorded before

fixture names were adjusted without changing scientific comparisons. The adjusted
three-file CTL fixture was executed separately against copies of the committed
sample binaries and passed without Fortran execution. No Windows
runtime certification, high-resolution conversion or package assembly is claimed.
