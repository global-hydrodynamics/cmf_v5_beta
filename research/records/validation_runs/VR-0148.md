## Scope, findings and compatibility

Area: development infrastructure and documentation. The prior root `util/` held a standalone month-length helper, while `tools/` held output-description tools. The maintainer explicitly requested their consolidation directly under `tools/`, with unchanged calculation logic and existing Task IDs.

The source accepts two positional integers (year, month) and writes a list-directed integer month length to stdout, with no data-file I/O. The Gregorian leap-year rules include the explicit year-zero February override to 28 days. Missing/malformed arguments rely on Fortran read errors; there is no month-range validation. Source bytes were preserved exactly, including the eight-character argument buffer and existing invalid-input behavior.

Dependency inspection covered tracked text (Markdown, Shell, Python, Fortran, Makefiles and configuration) and a read-only search of local reference files, including ignored files. No executable named `igetday` existed in root `util/` before the change. There is no discovered PATH export or bare-command invocation of the shared executable. The only tracked runtime calls to the shared helper are the two starting/ending month calculations in `gosh_test/legacy/test3-jpn_fcast.sh`; both now use `$BASE/tools/igetday`. Its existing BASE/working-directory convention was preserved. The v5 compile wrapper still builds only `src_main/`; users build the helper separately.

The independent `src/igetday` targets in `etc/downscale_flddph/`, `etc/n-year_flood_depth/script/`, and `etc/runoff_preset/` remain unchanged. Executed calls occur in downscale t01/t02/s11 and runoff-preset s02; n-year t02 has a commented call. The `day_clim` and `ave_clim` programs have their own internal `igetday` functions. No shared-helper dependency was found in active Tutorial, Visualization, map or inp workflows.

Both requested files were moved with `git mv`. The Makefile now includes only `../config/Mkinclude`, with an explicit missing-config diagnostic. It uses FC, FFLAGS, LFLAGS, legacy LFLAG and INC; no model/module objects or NetCDF libraries are required. The old Makefile used adm/Mkinclude and LFLAG; the v5 templates use LFLAGS, so both linker-flag spellings are accepted. Target and broad local clean patterns are preserved; all/clean are phony. The archive script's one source-directory copy now selects tools instead of util; its version and other v4 paths are unchanged. No archive was generated and no v5 package validity is claimed. README navigation and the root policy's directory inventory now identify tools.

Intentional old references remain in historical source/workflow descriptions (`docs/model_source_workflow_plan.md`, `src_main/README.md`), research evidence, and migration explanations in the current README/status. The untracked `legacy/gosh/compile.sh` still builds `util`, and its Japan forecast script still calls `$BASE/util/igetday`; `legacy/adm/README.md` also names the old Makefile. Those reference copies are unchanged per the instruction not to edit unmanaged files. They would need separate adaptation before execution against the v5 layout. Other existing legacy path issues are outside this task.
