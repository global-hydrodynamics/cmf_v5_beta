## Survey Report — Existing behavior and dependencies

- `analysis_river_point_info.py` accepted `xy IX IY` and `latlon LAT LON`, printed a report, and selected high-resolution assignment maps in the order 15sec then 1min before coarse geographic containment.
- Its base and high-resolution readers named Binary files directly, while `mod_map_io` already provides shared NetCDF raster reads and an explicit `--map-format binary` compatibility mode.
- The preserved historical implementation is `map/src/src_param/get_rivinfo.F90`. It uses one-based grid indices, latitude-before-longitude inputs, the same 15sec/1min assignment priority, and coarse containment fallback.
- The Mekong sample includes NetCDF base maps plus `1min/1min.catmxy.nc`; inspection with `ncdump -h` showed the high-resolution assignment variables are `catmxx` and `catmyy`.

## Work Report — Implementation

- Added `get_river_point_info.sh`, a thin positional-argument wrapper that invokes the shared Python program and leaves parsing and processing to Python. It writes no files; ordinary Shell redirection can save stdout.
- Replaced `a01-river_point_info.sh` with `a01-sample_get_river_point_info.sh`, which documents and runs both sample queries.
- Updated the Python reader to choose `.nc` inputs by default through shared map I/O, while preserving explicit `--map-format binary`. High-resolution `catmxy` reads use the selected representation and retain the existing tile priority and coordinate formulas.
- Updated shared and Mekong-local analysis READMEs, Python migration status, and focused tests. No scientific data or Fortran source was changed.
