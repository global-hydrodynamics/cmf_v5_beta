# VR-0286 — f03b Mekong bifurcation coordinate validation

- Date: 2026-11-28.
- Task: DT-0239.
- Source commit: `35a5796606e18b257c8568d5e7a29ba061f92835`; pre-existing worktree changes were preserved.
- Environment: macOS arm64; repository CPython 3.12 `.venv`; NumPy, NetCDF4, and Matplotlib; Agg backend.
- Dataset: Existing `map/mekong_15min/bifprm.csv`, `bifprm.nc`, `lonlat.nc`, and required map inputs. No data were modified.

## Checks

- Compared destination outlet coordinates for all 425 paths passing the existing index and width checks. All 425 exceeded the old `1e-5°` tolerance. Maximum absolute differences were `0.00041962°` longitude and `0.00041771°` latitude; none exceeded `0.0006°`.
- Compared CSV `end_lon`/`end_lat` rounded values converted to float32 against `bifprm.nc`: all 425 values matched exactly on both axes.
- Ran `f03b-vector_river_map-extended_network.py` with the real Mekong map and wrote the PNG to `/private/tmp/f03b-vector_river_map-extended_network.png`. The program reported 0 invalid bifurcation indices, widths, or outlets, with 18 channel and 121 overland bifurcations visible in the selected extent.
- Visually inspected the generated PNG; the extended channel, bifurcation, and headwater-guide network rendered.

## Result and limits

The coordinate check and f03b render passed. The error was caused by comparing
three-decimal supplementary CSV coordinates against `lonlat.nc` at a tighter
tolerance than their storage precision permits. The validation confirms the
Mekong case and rendering path; it does not establish consistency for every
map dataset.
