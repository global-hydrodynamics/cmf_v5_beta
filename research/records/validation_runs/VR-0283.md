# VR-0283 — Mekong high-resolution COG and p01-f04b functional check

- Date: 2026-11-28.
- Task: DT-0236. Events: EV-0898–EV-0900.
- Source commit: `35a5796606e18b257c8568d5e7a29ba061f92835`; worktree contained the preceding DT-0235 changes.
- Environment: macOS; project `.venv` CPython 3.12, Rasterio 1.4.1, netCDF4 1.7.2, Panel 1.5.5, Bokeh 3.6.2.
- Data: existing `map/mekong_15min`; source rasters and COGs were read-only.

## Checks

- Called `discover_tiles()` with the real map. It found `1min/1min`, registered
  `catmxy` and `visual` COGs (and the other available COG fields), and emitted
  no invalid-product messages.
- Read representative pixel windows from both COGs; categorical values and
  paired catmxy planes were returned with their native integer types.
- Checked `PresetLibrary.missing_products("p01-f04b", ...)`; result was empty.
- Applied p01-f04b to a real `Explorer`, confirmed one channel-pixel image,
  14 rendered channel bifurcation segments and 83 overland segments, and
  exported a 565,930-byte PNG to a temporary directory. The saved image was
  visually reviewed.
- `pytest` is not installed in the active isolated `.venv`, and no browser GUI
  interaction tool is available in this environment. Focused regression test
  cases were added but could not be run under pytest.

## Results and limits

The reported high-resolution Missing state was not reproducible in the current
checkout: `location.csv`, COG discovery, sampling, Gallery availability and
the exported p01-f04b rendering all succeeded. Runtime checks also exposed the
three-decimal supplementary bifurcation-coordinate precision mismatch; the
Explorer comparison was aligned to that established storage precision without
changing destination-index connectivity or weakening COG validation. The PNG
render path was verified, but an interactive browser/GUI session was not.
