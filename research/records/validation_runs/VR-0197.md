## Implementation and contracts

The existing generator accepts --input (map-dir-relative filename or absolute
path directly inside that directory), --reference-binary (literal registered base
filename) and --variables (comma-separated registry names). Explicit metadata
selection requires one input to prevent applying one array meaning to every
Binary in the directory. Exact reference is preferred when names are ambiguous;
a single variable prefers its canonical same-name .bin definition. Otherwise
candidate groups must identify one unique complete file. Unknown names/keys,
wildcard references, missing inputs, invalid dimensions/size are explicit errors.

CTL describes physical record offsets: variables select a full reference layout,
not an output subset. A nexty request retains nextx/nexty in their original order.
No missing record is collapsed, dtype/sentinel/geometry values remain CSV-driven,
and dset/output filenames retain the real input basename. Positive numbered MPI
files share mpireg.bin automatically; the standard-only rule is ASCII/positive,
matching the established Binary-to-NetCDF convention. The CTL script remains a
standalone standard-library program, including in disposable copied fixtures.

Default s99 scans normal files as before, then uses Shell-owned VARIANTS entries:
subbsn-sample.bin:subbsn.bin, subcol-sample.bin:subcol.bin and
upbasin-*.bin:upbasin.bin. Only existing matches are processed. Unknown variant
files may appear as SKIP in the initial scan before the explicit mapping pass.
Single --input mode bypasses unrelated base/high-resolution scans. Existing
--dry-run, --overwrite/default and --no-overwrite rules are preserved.
High-resolution NetCDF directories without .bin inputs still yield no CTLs.

The shared params/format and Mekong wrapper copies agree. Three existing local
Global/Japan wrappers were compared byte-for-byte with the original shared
version before replacement; no custom edits were overwritten. Backups retained
in a temporary directory. Original Binary/CTL data and external additional-data
store are not modified by this task.

The previously documented Python3.11 int.is_integer AttributeError for integer
default sentinels is fixed by applying float(value).is_integer after the existing
numeric/range checks. This directly affected the user execution path; missing
values and GrADS signed-byte handling do not change. New tests exposed macOS
/var versus /private/var path spelling differences for absolute inputs; normalize
only the parent while retaining the input basename. Initial failures precede
the successful final runs and are not counted as passing checks.
