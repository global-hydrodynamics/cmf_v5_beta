## Survey Report — Existing behavior and constraints

- `analysis_upbasin.py` already accepts `IX IY [OUTPUT]`; `upstream_mask()` labels cells whose downstream paths reach the selected cell, preserving 1 for the selected upstream basin, 0 for other network cells, and -9999 outside the modeled network.
- The shared `mod_map_io` parser defaults to NetCDF and the existing writer handles `.nc` output. The generic wrapper can therefore reuse the established implementation without adding a second calculation or changing the Python CLI.
- The Python output writer resolves NetCDF variable names from `map_variables.csv`. Coordinate-qualified output filenames such as `upbasin-62-93.nc` need to retain the registered variable name `upbasin`.
- `script_params/x02-upbasin.sh` selects a GRDC station and invokes the Python IX/IY/OUTPUT interface directly; it is a separate workflow and remains unchanged.

## Work Report — Implementation

- Added `calc_upbasin.sh`, which accepts only `xy IX IY [OUTPUT.nc]`, uses one-based grid indices, defaults to `../upbasin-${IX}-${IY}.nc`, and resolves relative output paths against its map-local `script_analysis/` directory. It calls `analysis_upbasin.py IX IY OUTPUT`, prints the selected cell and output path, and leaves the grid count/area summary to the existing Python program.
- Replaced `a02-upbasin.sh` with `a02-sample_calc_upbasin.sh`. The sample prints user-facing instructions and runs cell (62, 93) into `./upbasin-sample.nc`; it creates no separate text report.
- Generalized shared NetCDF registry-name resolution for registered variables with descriptive filename suffixes, preserving `upbasin` as the NetCDF variable in coordinate-labeled outputs.
- Updated the shared analysis README, the directly affected Mekong-local README/sample copy, and focused workflow tests. The GRDC `x02` script remains independent and continues to call the existing Python positional interface directly.
- No scientific calculation, model input, or map data was changed.
