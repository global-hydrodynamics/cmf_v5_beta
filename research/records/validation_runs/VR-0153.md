## Presets and metadata strategy

11 preset IDs reference the canonical CSV: p01-f01a/c, p01-f02c, p01-f03a/b,
p01-f04a/b, p01-f05a/c/d/f. They cover log upstream-area raster, pastel basin
colors, gray subcol with shade-rainbow area-colored links, stored outlet vectors,
extended bifurcations, assigned catchments with/without channel pixels, and gray/
pale-terrain elevation/floodplain height. Titles, scientific purpose and Gallery
documentation come from the existing catalog. The small new CSV contains only
flat settings plus gallery_id references; no parallel scientific metadata, YAML,
nested serialized configuration or Gallery script imports.

Input validation names missing exact raster/network/outlet/bifurcation/tile
products and disables Apply; validation precedes widget mutation. Presets leave
extent unchanged by default, with a separate opt-in suggested extent. Subsequent
edits are allowed and marked Custom (modified); pan alone is excluded from that
comparison. User settings remain JSON version 2 and v1 is accepted.

Essential scientific choices are reproduced, not exact publication graphics.
Explorer retains straight flexible links (Gallery f02c curves them) and existing
full-network classes (f04 Gallery uses visible/path distributions). Symbolic
arrows, overlay widths, layout and typography can differ. No modified preset is
represented as newly Gallery-approved science.

## Native selection and PNG

SelectionState separates clicked lon/lat, native fine row/column, assigned coarse
river cell, complete assignment geometry and status. Existing selected remains
a compatibility alias for the river cell; nextxy supplies only downstream links.
The click reads the actual native catmx/catmy pixel, validates both one-based
indices, and resolves the assigned cell without geographic/nearest-cell fallback.

A lazy sparse assignment index scans the selected tile in bounded row blocks
once. Pixel counts and native bounding boxes locate later extraction. Comparing
both assignment records selects every matching pixel. Native one-pixel halos
across processing blocks and exposed N/S/E/W edges preserve actual tile limits,
holes, missing neighbors and disconnected groups. Collinear runs merge without
connecting gaps. A 24-entry boundary LRU avoids repeated extraction.

Dedicated magenta browser renderer lies above general boundaries and networks,
even when general catchment outlines are disabled. The viewport only filters
transferred runs; full geometry and counts survive pan/zoom/styles/presets. PNG
uses the same complete coordinates and axes clipping. Unassigned/mixed pixels
clear old selection and show raw codes; changing tile source clears with a
message. Coarse selection stays geographic; terrain does not infer a catchment.
The boundary is a stored assignment, not a new watershed or observed basin.

## Remaining limits and unexecuted checks

Selection is complete within the selected tile; cross-tile stitching/mosaics,
global asynchronous indexing and global performance certification are not
implemented. First valid selection indexes one whole tile in bounded chunks;
large assignment boxes or fragmented outlines can still be expensive. No new
geospatial dependency. Tall geographic views can exceed viewport height to
preserve aspect. Optional thumbnails and two-way Gallery synchronization are
not implemented. Selection is not saved in user JSON. Windows native launch
is **SKIP** on this macOS host; existing wrappers are unchanged. macOS launches
through the same CLI tested here; Finder folder-dialog flow was not rerun in
v3 (previous evidence remains VR-0151/0152). No model simulation or independent
hydrological validation is claimed.
