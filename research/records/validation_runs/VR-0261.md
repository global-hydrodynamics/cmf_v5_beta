## Installation limitations and observations

1. CPython 3.10.8 was installed under the temp directory through uv; repository `.venv` remained unchanged.
2. PyPI has no macOS arm64 wheel for Rasterio 1.3.4. The profile's normal install attempted its source archive. Build isolation failed because the legacy source expected `pkg_resources`; retry with the temporary environment's build tools failed on missing Cython. `gdal-config` is absent. No system GDAL or Homebrew components were installed.
3. PyPI's lmoments3 wheel is named `1.0.4.post1` but embeds version metadata `1.0.4`; pip index resolution rejects `lmoments3==1.0.4`. The 2022 requirements profile now pins the official universal wheel URL by SHA-256, and its installed metadata reports 1.0.4.
4. The converter CLI planner attempt did not resolve the registered file stem, so the representative 2024 COG validation invoked the same `convert` operation with an explicit registered task. It passed full native-pixel verification. The CLI/planner issue is outside this dependency task and requires a separate focused fix.
5. The direct-source `shade_rainbow` render in 2022 validates the colormap code path only; local `cmf_colormap` package metadata requires Matplotlib>=3.7 and cannot be claimed installed/compatible as a package under Matplotlib 3.6.2.

These results are host- and workflow-specific. 2024 focused paths pass. 2022 core NetCDF/metadata/map-analysis and headless plotting checks pass on the partial profile, but Rasterio-dependent and current Explorer workflows remain unverified.
