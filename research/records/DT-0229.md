- Authorization: maintainer request to update the output and restart CTL generators for current v5 map metadata.
- Validation: [VR-0276](validation_runs/VR-0276.md).

## Prior constraint and change

tools/scripts/generate_output_ctl.py and generate_restart_ctl.py located only the positional params.txt file, so a Mekong v5 run using params.nml and a paired two-group DIMINFO failed before model execution. The scripts now share tools/scripts/map_geometry.py. The helper locates map metadata from CNEXTXY, CGRAREA, or CDIMINFO; params.nml GRID/DOMAIN is authoritative. When only the configured two-group DIMINFO is available, it derives square-grid spacing from DIMINFO bounds and model dimensions. INPUTDIM is not used for output axes. If both v5 files are available, model-grid dimensions, bounds, and resolution are checked. Legacy params.txt remains available for older maps.

The GrADS axis origin/orientation, TDEF and record calculations, data ordering, endian handling, variables, and restart Float32 preview behavior were left unchanged.

## Validation and limits

Five focused tests pass. Actual Mekong output and restart CTLs use XDEF 80 LINEAR 90.125 0.25 and YDEF 120 LINEAR 5.125 0.25. An isolated mek01-default_run.sh generated all planned CTLs, then the available copied executable stopped at runtime while reading NML DIMINFO. The current source executable was absent, so this does not establish a successful current-build model run.

## Compatibility impact and knowledge-gap review

No scientific calculation or parameterization was intentionally changed. This fixes metadata compatibility at the CTL generation boundary. The short knowledge-gap review found no new scientific question. A current src_main/MAIN_cmf build should be used for a later end-to-end sample run to validate the model's separate NML reader; that is outside this CTL repair.
