# DT-0243 — Modernize Tutorial01 Shell and learner documentation

- **Date:** 2026-11-28
- **Branch:** `feature/package-builder`
- **Starting commit:** `35a5796606e18b257c8568d5e7a29ba061f92835`
- **Area:** documentation; simulation workflow
- **Scope:** Update the Tutorial01 standalone workflow and its learner/developer design documents to use the current CaMa-Flood root setup, shared Shell helpers, and map/input-matrix formats.

## Prior constraint

The standalone tutorial script used its own root variable and error/progress reporting. Its learner documentation described the earlier map metadata and input-matrix formats and included developer-only Package Builder/reset material.

## Change and enabled capability

The script now requires `CMF_V50_ROOT`, sources `tools/cmf_shell_functions.sh`, and uses `cmf_check_init`, `cmf_check_step`, and `cmf_check_success`. Repository paths are rooted at `CMF_V50_ROOT`; the Fortran NAMELIST field remains `CMF_BASE` and receives that root value. Step totals account for Binary versus NetCDF output configuration. The learner README and both design documents explain root setup and shell activation, optional Python setup/activation, current NetCDF map and input-matrix files, Binary runoff/model output, and the tutorial run products. Developer-only setup/reset content was removed from the learner README.

## Scientific and compatibility impact

No scientific algorithms, parameters, dates, grid selections, runoff inputs, or model output formats were changed. The existing NAMELIST variable `CMF_BASE` and Binary runoff/output behavior are preserved. Current Mekong map metadata uses `params.nml`, root-level NetCDF variables, `location.csv`, `diminfo_repo-mek_1deg.nml`, and `inpmat_repo-mek_1deg.nc`.

## Validation and limits

See [VR-0290](validation_runs/VR-0290.md). `sh -n` passed. The full 40-day tutorial simulation ran successfully using the already-built `src_main/MAIN_cmf` and the bundled Mekong inputs. It ran from a disposable temporary copy of the script so the existing Tutorial01 `out/` tree was not overwritten. Five 40-record Binary outputs, their CTLs, the model log, and the end Restart/CTL were confirmed. This is workflow evidence for the tested checkout, not scientific validation of the simulated values. `make all`, interactive root configuration, and the optional Python environment setup were not rerun.

## Knowledge-gap review

Checklist completed. No material new scientific or architectural gaps were found. Setup scripts' interactive shell-startup behavior is documented from their current interface; this task did not test edits to a user's shell configuration.
