# DT-0209 — Replace TOML map geometry metadata with Fortran Namelist

- **Branch:** `feature/package-builder` (maintainer-directed continuation)
- **Starting commit:** `b530a2e69529260d386f9621778a4cc09cdd56dc`
- **Status:** Implemented; focused validation passed. No commit or push requested.

## Survey findings

The preceding DT-0208 implementation made `params.toml` authoritative for maintained Python map geometry readers and writers. `map/tools/code/map_metadata.py` was the central reader; regionalization wrote TOML; conversion, CTL, and layout tools referred to it. Python 3.10 support used the extra `tomli` dependency. The model source under `src_main/` does not read map geometry metadata, while historical and retained Fortran map-preprocessing programs still read `params.txt`. Binary/CTL workflows also retain a TXT compatibility path.

The maintainer's new task selected Fortran Namelist for small structured configuration because Fortran reads it natively and Python can use `f90nml`. The eight geometry values, cell-edge convention, and north-to-south raster orientation remain unchanged. No broader migration of `diminfo` or `location.txt` was in scope.

## Work report

Replaced the shared TOML reader/writer with one `f90nml`-based `params.nml` reader and a writer for the `&GRID` and `&DOMAIN` groups. Regionalization and direct geometry consumers now use NML-first lookup with TXT-only legacy support and numerical conflict detection when both files exist. The legacy-copy utility now only writes `params.txt`; TOML conversion code was removed. Requirements, registry metadata, map/conversion/regionalization documentation, and focused tests were updated.

A filesystem scan found five `params.toml` files: Mekong root and `binary/`, Global, Rhine, and TE-Japan. All five produced `params.nml`; every parsed value matched the prior TOML and corresponding legacy TXT; each TOML was removed only after verification. Only the two tracked Mekong NML files are Git-tracked. The Global, Rhine, and TE-Japan metadata remain ignored/untracked under the existing map policy. No raster datasets or scientific arrays changed.

## Scientific and compatibility impact

No scientific algorithm, parameter, array, index convention, or coordinate value changed. `params.nml` is the maintained v5 geometry source. `params.txt` remains where legacy Fortran/Binary consumers need it, and mismatched NML/TXT pairs are rejected. TOML is retired for this interface. Remaining work is limited to any external package or user scripts that may have hard-coded `params.toml`; none were changed outside the repository.

## Verification

See [VR-0253](validation_runs/VR-0253.md): 30 focused tests passed; the Mekong NetCDF map reader loaded `nextxy.nc` using NML geometry; a small GNU Fortran program read both Namelist groups; the registry and nine Shell wrappers validated. The initial repository-wide `compileall` attempt could not write bytecode into read-only `__pycache__` directories; focused `py_compile` using a temporary cache directory passed for all changed Python files.

## Knowledge-gap review

No material new scientific gap was found. Compatibility risk is limited to external consumers of the retired TOML filename; repository consumers were updated. Legacy TXT removal is deferred because historical Fortran and Binary/CTL paths still consume or produce it.
