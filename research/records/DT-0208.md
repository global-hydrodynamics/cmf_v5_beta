# DT-0208 — Migrate map geometry metadata to TOML

- **Branch:** `feature/package-builder` (maintainer-directed continuation on the current branch)
- **Starting commit:** `75fc2e50be720be631796b5264d9906ec68b1fec`
- **Status:** Implemented; focused verification passed. No commit or push requested.

## Scope and prior constraint

Base-map geometry was maintained in eight-record `params.txt` files. Current v5 Python readers and regional output needed a shared authoritative format while older Fortran and map-local workflows still consume TXT. The migration covers maintained map tools and all existing on-disk `map/**/params.txt` files, including ignored local datasets, without adding ignored datasets to Git or deleting compatibility files.

## Change and compatibility

Added `map_metadata.py` for the shared TOML schema and TXT fallback, with numerical conflict detection when both are present. Added the safe, rerunnable `migrate_map_params.py`; it creates a TOML file only when absent, verifies all eight geometry values before publishing, and refuses to overwrite conflicts. Maintained readers, converters, CTL generation, and regional cropping now use the shared reader; cropped domains write TOML. CTL support can generate a legacy Binary-side TXT copy from the authoritative geometry. `src_main/` was inspected and has no `params.txt` dependency, so model source was unchanged.

The local scan found five existing TXT files: two tracked Mekong files and three files in ignored Global, Rhine, and TE-Japan maps. All five were converted and numerically verified; all original TXT files were retained for compatibility. The three ignored TOMLs remain ignored and untracked. No river-map raster or scientific values were changed.

## Scientific and compatibility impact

No scientific algorithm or model parameter changed. The new TOML files preserve NX, NY, NLFP, resolution, and geographic bounds. Legacy TXT remains readable; when both exist, values must agree. Remaining TXT consumers are legacy Fortran utilities, test fixtures, and Binary/CTL compatibility paths.
