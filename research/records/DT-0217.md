## Reproduced cause

On a clean checkout with the current floating root requirements, standard pip installation completed with NumPy 2.5.5 and netCDF4 1.7.5.1.post1. Importing netCDF4 failed with `ValueError: numpy.dtype size changed`. The 2024 fallback downgraded its pinned dependencies in place, but pip retained `panel-material-ui 0.17.0` from the standard environment; its Panel>=1.10 and Bokeh>=3.10 requirements conflicted with the fallback's Panel 1.5.5 and Bokeh 3.6.2 pins, so `pip check` failed.

## Change and compatibility behavior

When fallback is selected, `s02-python_setup.sh` now moves the current repository `.venv` to a temporary sibling backup and creates a clean virtual environment at the canonical `.venv` path using the same base Python. It installs the full 2024 profile and editable CMF Colormaps there, then runs `pip check`, principal imports, and `shade_rainbow` validation. The previous environment remains intact in the backup until validation passes. On success, the backup is removed; if installation, validation, or interruption fails before success, the incomplete replacement is removed and the previous `.venv` is restored. The process does not individually uninstall packages or rely on pip to remove stale transitive distributions.

## Work Report and validation

The exact failure sequence was rerun from a fresh temporary checkout: fresh `.venv`, standard install, netCDF4 ABI import failure, clean 2024 fallback, successful `pip check`, and successful imports of NumPy, pandas, xarray, netCDF4, SciPy, Matplotlib, Rasterio, tifffile, f90nml, Pillow, requests, Param, and CMF `shade_rainbow`. NumPy resolved to 1.26.4, netCDF4 to 1.7.2, and `panel-material-ui` was absent from the clean environment. A separate failure-path test confirmed that when both installs fail, the original `.venv` marker and interpreter are restored. See [VR-0263](validation_runs/VR-0263.md).

Updated the setup guides and superseded the limitation recorded in [DT-0216](DT-0216.md). No scientific code, model inputs, or global/system Python environments were changed. The test host was macOS arm64 with CPython 3.12.3; other OS/CPU combinations remain unverified.
