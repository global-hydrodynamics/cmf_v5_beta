# DT-0212 — Separate bifurcation channel and overland width formats

- **Branch:** `feature/package-builder`
- **Starting commit:** `730cde546229154bca74eac3f9a91433c8bc02cc`
- **Status:** Implemented; targeted CSV, NetCDF, MPI, visualization-reader, and Fortran compile checks completed. Several older integration fixtures still target retired map paths/workflows. Changes remain uncommitted.

## Objective and scope

Standardize bifurcation widths so the river-channel width is distinct from overland widths across `bifprm.csv`, `bifprm.nc`, model input readers, map tools, and affected visualization consumers. Keep `bifori.txt`, its layer ordering and calculations, and the existing model numerical routines unchanged. The task instruction is recorded in [EV-0825](../events.csv); the interface rationale is summarized in [DR-0065](discussions/DR-0065.md).

## Survey report

Source inspection confirmed the existing first width is the channel width and subsequent widths are overland widths. The model's internal layout is `PTH_WTH(path, layer)`: internal layer 1 remains channel and layers 2 onward remain overland. `NPTHLEV` is allocated from the parameter file layer count; no separate run setting for selecting a subset of available overland layers was found. `NLFP` governs the model floodplain vertical layers and is not treated as an overland bifurcation count.

The tracked Mekong sample contains 382 finalized rows, four overland width layers plus the channel width, and a tracked legacy NetCDF file using `width(layer,path)`. The old tracked CSV and NetCDF values were compared before the NetCDF migration. Every path ID, endpoint, coordinate, basin identifier, non-width value, and five width values matched exactly after mapping old `width_1` to `riv_width` and old `width_2..5` to `ovl_width_1..4`. The original `bifori.txt` is unchanged.

## Work report

- The generator now writes `riv_width` and consecutive optional `ovl_width_1..N` columns. It preserves row ordering, formatting precision, filtering, and the legacy internal first-width/channel interpretation.
- The shared Python CSV reader resolves fields by name, tolerates whitespace and unknown diagnostic columns, accepts zero overland layers, and rejects malformed or non-consecutive overland columns.
- The CSV-to-NetCDF converter writes `riv_width(path)` and optional `ovl_width(layer,path)`. A channel-only file omits both `layer` and `ovl_width`; there is no combined `width` variable.
- Model CSV and NetCDF readers map the new external variables to the unchanged internal array. The legacy text reader remains available; the old combined-width CSV/NetCDF schema is not guessed or silently reinterpreted.
- Updated the map metadata specification, variable registry descriptions, model and map-tool READMEs, the Mekong/Rhine bifurcation workflow READMEs, Tutorial 02 design notes, and affected Explorer/river-map readers and tests. Updated two Mekong integration test paths to the current map-root NetCDF layout. No Gallery figure or source topology was changed.
- Migrated the tracked Mekong `bifprm.csv` and `bifprm.nc`. The NetCDF now has `path=382`, `layer=4`, `riv_width(path)`, and `ovl_width(layer,path)`.

## Validation

See [VR-0257](validation_runs/VR-0257.md). Highlights: new format and MPI-focused suites passed 16 tests; the current-layout Explorer/river-map integration suite passed 16 tests; a direct Mekong reader check loaded all 382 rows and resolved outlet segments; old CSV/NetCDF and migrated CSV/NetCDF values matched exactly; the three changed Fortran modules compiled to a temporary directory; the map registry and Python syntax checks passed. Five older bifurcation migration tests remain incompatible with current map-local inputs and Python-wrapper layout. These limitations do not establish full model-reader runtime equivalence.

## Scientific and compatibility impact

No bifurcation physics, equations, parameterization, path selection, path order, width values, or `bifori.txt` behavior was changed. External width names now state physical meaning explicitly; internal model ordering remains the same. CSV, NetCDF and visualization interfaces change for bifurcation width fields, so old combined-width CSV/NetCDF products require explicit migration before use by the standardized readers. The preserved legacy `bifprm.txt` path is unchanged.

## Knowledge-gap review

The scientific interface checklist is complete for source contracts, sample values, zero-overland representation, sorting, consumer field mappings and compatibility boundary. One material question remains: the model has no independent configuration to request a subset of available overland bifurcation layers. Current behavior uses every overland layer present in the file. `NPTHLEV` controls internal pathway flow/restart/output dimensions and current activation; `NLFP` is a separate floodplain discretization. A future setting must define default/backward compatibility, path activation, `pthflw` and restart dimensions together. This is recorded as open [KG-0041](knowledge_gaps/KG-0041.md). It did not block separating the external data fields, and no new runtime option was introduced in this task.
