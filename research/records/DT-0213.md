# DT-0213 — Migrate bifori source table to CSV

- **Branch:** `feature/package-builder`
- **Starting commit:** `730cde546229154bca74eac3f9a91433c8bc02cc`
- **Status:** Implemented; focused source-contract and registry checks passed. The optional generator equivalence check was skipped because `f90nml` is unavailable. Changes remain uncommitted.

## Objective and scope

Make named-column `bifori.csv` the source interface for maintained v5 bifurcation generation and regional cropping, while preserving the existing algorithms, source values, legacy TXT data, FLOW, Fortran, and external map datasets. The task specification is indexed in [EV-0831](../events.csv); the format policy is in [DR-0067](discussions/DR-0067.md).

## Survey report

The tracked Mekong source has 687 paths and 21 width values per path: the channel width plus 20 overland widths. Its legacy header has a count preamble; each data record contains endpoint indices, length, elevation, widths, and the final coordinate pair. Existing interpretation assigns the pair to latitude then longitude even though the legacy header says `(lon,lat)`. Explicit CSV fields remove that ambiguity. The maintained parameter generator uses `BIFLAYER` as a total width-field count, including the channel; the default value 5 selects `riv_width` and the first four overland widths.

The preserved Fortran source remains a historical reference and continues to consume the old TXT representation. FLOW production and external maps were not changed. Other datasets that have only `bifori.txt` require a separate explicit conversion before running maintained CSV-based v5 consumers.

## Work report

- Added `map/tools/code/mod_bifori_csv.py` to read and write named source tables, validate required fields and consecutive optional width columns, retain additional columns, and apply the existing regional endpoint shift/filter rules.
- Updated `param_bif_set_params.py` and `region_cut_bifway.py` to require `bifori.csv`; the regional crop writes `bifori.csv`, preserves source path IDs and optional columns, and retains the existing strict interior/edge-mask selection.
- Added `map/mekong_15min/bifori.csv`, keeping `bifori.txt` unchanged. All 687 rows, source precision, width values, and coordinate values are preserved by parsed-value comparison.
- Updated the bifurcation shell comments, map registry and metadata specification, parameter/regional workflow documentation, migration-status and migration-plan references, Mekong sample validation, and focused tests/benchmark comparison.
- The parameter generator still creates `bifprm.csv` with a consecutive ID after filtering; source `path_id` is not substituted for that configuration-specific output identifier.

## Validation

See [VR-0259](validation_runs/VR-0259.md). The CSV contract suite passed 8 tests; its generator comparison passed when run with a temporary shim for the unavailable `f90nml` dependency. The Mekong generator produced 382 rows exactly matching the tracked `bifprm.csv`. Registry validation, focused Python syntax parsing, and `sh -n` for the three s03 wrappers passed. The shim did not validate the third-party Namelist parser; no model simulation or FLOW-side validation was performed.

## Remaining limitations

1. The generator's full Mekong result comparison remains to be run in an environment containing `f90nml` and the existing NetCDF dependencies.
2. External maps with only `bifori.txt` were deliberately not modified and cannot use the maintained CSV-only reader until converted.
3. FLOW's producer, legacy Fortran references, and historical v4 workflows remain on TXT and were intentionally left intact.
