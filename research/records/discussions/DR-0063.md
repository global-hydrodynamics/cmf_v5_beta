## Question and context

The recently adopted TOMl geometry metadata interface required Python's `tomllib`/`tomli` and was not directly readable by Fortran. The maintainer directed replacement with Fortran Namelist for map geometry only.

## Alternatives discussed

Continue with TOML and add/retain a Fortran TOML parser; keep the legacy eight-record TXT as the shared format; or adopt standard Fortran Namelist and Python `f90nml`. The task selected the latter and explicitly excluded `diminfo` and `location.txt` migrations.

## Maintainer decision and rationale

Use `params.nml` with `&GRID` and `&DOMAIN` groups as the authoritative v5 map geometry format. The same configuration can be read by native Fortran Namelist facilities and the Python `f90nml` package, avoiding a separate Fortran TOML dependency.

## Implementation instruction

Preserve the eight values and scientific conventions; update maintained Python readers/writers, regionalization, converters, CTL tooling, docs and registry; retain TXT-only legacy support and reject inconsistent NML/TXT pairs. Migrate all local `params.toml` files under `map/` only after verification, without changing ignored-map tracking policy.

## Outcome or unresolved questions

Implemented and recorded in DT-0209. No repository consumer of `params.toml` remains except the metadata specification's explicit retirement note. External consumers are outside this audit.
