# DR-0064 — Centralize legacy map-metadata compatibility

## Question and context

The high-resolution area inventory was historically stored as `location.txt`. The v5 NetCDF-first map layout needs one standard representation, while existing Binary maps and external map installations may still depend on the legacy text descriptor.

## Evidence examined

Maintainer-provided architecture decision and the current map readers, producers, Binary/NetCDF conversion scripts, sample map files, and local map directories.

## Alternatives discussed

Continuing to add legacy parsing to each consumer would duplicate format handling throughout scientific code. Immediately removing all TXT support would break active Binary workflows and map directories that have not yet been migrated.

## Maintainer decision and rationale

The standard v5 formats are `params.nml`, `diminfo_<ROFFTAG>.nml`, and `location.csv`. Legacy conversion is to be centralized in explicit, bidirectional tools under `map/tools/script_format_conv/`. Ordinary v5 workflows should consume the standard formats directly. The new conversion tools are a separate task and were not implemented here. Existing compatibility may remain temporarily where removing it would break an active workflow; external metadata must not be deleted or assumed migrated.

## Implementation instruction, if any

For the current location-inventory migration, update the standard CSV format and its maintained consumers. Do not add another permanent `location.txt` fallback to ordinary workflows. Preserve original external descriptors and record remaining compatibility code for later cleanup.

## Outcome or unresolved questions

The standard schema is `iarea,carea,west,east,south,north,nx,ny,csize`; each data row identifies one listed tile, and no count or inferred missing tiles are stored. Existing Binary conversion boundaries and Map Explorer access to unmigrated maps retain limited TXT support for now. Those paths are inventoried in [DT-0211](../DT-0211.md).
