# DR-0067 — Standard bifurcation source table uses named CSV

- **Date:** 2026-11-27
- **Task:** [DT-0213](../DT-0213.md)
- **Source:** Maintainer task specification in the active Codex conversation; no stable archive ID.

## Decision

Maintained CaMa-Flood v5 bifurcation preparation and regional cropping consume and produce a named-column `bifori.csv`. The legacy count-prefixed `bifori.txt` remains untouched as a source reference; ordinary maintained Python workflows do not add a TXT fallback. Conversion of other external map datasets and changes to FLOW's producer are outside this task.

`BIFLAYER` counts total width fields including `riv_width`. Thus, `BIFLAYER=5` selects the channel and the first four overland widths. The source `path_id` is preserved during regional cropping; `bifprm.csv` continues to assign its own sequential IDs after filtering.

## Rationale

Named fields make the channel/overland distinction explicit, allow optional source columns to pass through regional cropping, and avoid a count/header parser in normal v5 readers. Keeping FLOW and external map data unchanged limits this migration to the repository-owned interface and Mekong sample.

## Consequences

Maps with only `bifori.txt` need explicit migration before using the maintained CSV-based v5 bifurcation workflow. The original Mekong TXT is retained for comparison. The CSV schema and compatibility boundary are documented in `variable_table/map_metadata_spec.md`.
