# DR-0065 — Distinguish bifurcation channel and overland widths

- **Discussion ID:** DR-0065
- **Linked event ID(s):** EV-0825–EV-0827
- **Source type:** Codex task instruction and maintainer clarification
- **Source reference:** Active Codex conversation and supplied task document
- **Source access:** restricted
- **Maintainer review:** pending

## Question and context

The existing `bifprm` formats name every width as a numbered floodplain layer, although the first width represents a river-channel bifurcation and subsequent widths represent overland bifurcation layers. The CSV and NetCDF interfaces need names that reflect those distinct components without changing model calculations.

## Evidence examined

The `bifori.txt` reader and bifurcation parameter generator, the existing Mekong CSV and NetCDF values, the model `READ_BIFPARAM` initialization and `PTH_WTH` consumers, MPI sorting/aggregation code, and current visualization readers.

## Alternatives discussed

Retaining a combined `width(layer,path)` external variable would preserve the ambiguity. Treating the river-channel width as overland layer zero would misstate its physical meaning. Adding a second combined-width copy would create duplicate representations and consistency risk.

## Proposal (not yet a decision)

Use one authoritative `riv_width` field and consecutive overland-only `ovl_width_1..N` fields in CSV; represent them as `riv_width(path)` and optional `ovl_width(layer,path)` in NetCDF. Preserve the internal channel-first width array at the I/O boundary.

## Maintainer decision and rationale

The supplied task instruction authorizes this interface migration, requires `bifori.txt` and scientific behavior to remain unchanged, permits unknown optional CSV columns, defines omission of `layer` and `ovl_width` for zero overland layers, and explicitly prohibits silently adding a runtime layer-count setting. The channel is not overland layer zero. This distinction makes the stored fields physically interpretable while leaving the current numerical routines intact.

## Implementation instruction, if any

Update maintained producers, readers, NetCDF conversion, sample products, directly affected visualization consumers, registry and documentation. Keep the existing internal layer 1 as channel and layers 2 onward as overland. Document any unresolved distinction between available data-file layers and layers enabled by a run; do not infer that count from `NLFP`.

## Outcome or unresolved questions

The CSV/NetCDF split and Mekong sample migration are implemented. The runtime still consumes every overland layer supplied by the bifurcation parameter file. An independent selectable count and its implications for pathway activation, `NPTHLEV`, `pthflw` and restart compatibility remain open in [KG-0041](../knowledge_gaps/KG-0041.md).
