# DT-0215 — Python dependency requirements audit and historical profile experiment

## Objective

Survey declared and actually imported Python dependencies across maintained CaMa-Flood v5 code, prepare 2024 and 2022 historical direct-dependency profiles, and evaluate whether the evidence supports a setup fallback.

## Scope and method

Reviewed root and component guidance, root and Map Explorer requirements, `s02-python_setup.sh`, maintained Python import sites under `map/`, `inp/`, `visualization/`, `tutorial/`, and `tools/`, existing environments, available sample NetCDF/map products, and PyPI release metadata. No scientific algorithm, Fortran source, or map data was modified. Existing repository `.venv` environments were inspected read-only. Historical environments and all generated outputs were isolated under `/private/tmp/cmf-dependency-audit`.

## Results

- Maintained sources directly import Pillow (`PIL`), `requests`, and `param` without explicit direct declarations in all affected requirements files. Added these declarations; no unverified minimums were invented for Pillow or requests.
- Created 2024 and 2022 direct-dependency snapshots. They are not full transitive locks.
- Retained existing minimum versions. Neither historical run represents exhaustive minimum-version validation.
- No setup fallback was introduced. The 2024 profile passed its focused runtime checks; the 2022 profile cannot be fully installed on this Apple Silicon host because its Rasterio pin has no compatible PyPI wheel.

## Validation

Host: macOS arm64. CPython 3.12.3 was already available. CPython 3.10.8 was downloaded using isolated uv 0.13.10 into `/private/tmp`; no repository `.venv`, system Python, or shared environment was changed.

**2024 profile:** all direct pins installed in a temporary CPython 3.12.3 environment, together with the local `visualization/cmf_colormap` package. `pip check` passed. netCDF4 1.7.2 built from its source distribution; Rasterio 1.4.1 installed from the macOS arm64 wheel. Passed checks: declared-package imports/version listing; synthetic NetCDF and GeoTIFF exact-value round trips; headless Matplotlib `shade_rainbow` PNG rendering; Mekong `params.nml` parsing; Tutorial 11 Rhine output read with xarray; and the COG converter's native conversion/verification function on Mekong `uparea.nc`, writing only under `/private/tmp`.

**2022 profile:** installed all pinned packages other than Rasterio in a temporary CPython 3.10.8 environment. The PyPI 1.0.4 `lmoments3` file is named `1.0.4.post1` while its internal metadata says `1.0.4`; pip's index resolver rejects the normal version pin. Installed the official PyPI wheel by immutable file URL (SHA-256 recorded in `requirements_2022.txt`). `pip check` passed for the installed subset. Passed checks: imports of NumPy 1.23.5, netCDF4 1.6.2, f90nml 1.4.3, pandas 1.5.2, xarray 2022.12.0, SciPy 1.9.3, Matplotlib 3.6.2, Panel 0.14.2, Bokeh 2.4.3 and other resolvable direct pins; synthetic NetCDF round trip; Mekong `params.nml` parse; Tutorial 11 monthly xarray read; headless Matplotlib `shade_rainbow` rendering from repository source; and `analysis_river_point_info.py --map-dir map/mekong_15min xy 19 6` against the real NetCDF map (one-based cell `(19,6)`, expected attributes printed).

The full 2022 profile install was attempted from PyPI. Rasterio 1.3.4 had no CPython 3.10 macOS arm64 wheel and pip attempted the source distribution. Build isolation first failed because the sdist expected `pkg_resources` from its build environment; retry without build isolation failed because Cython was not installed. `gdal-config` is absent on the host, so a native Rasterio/GDAL source build was not pursued. Rasterio/COG checks and current Explorer compatibility therefore remain untested for the 2022 profile. Panel 0.14.2/Bokeh 2.4.3 also do not meet today's Explorer requirements.

A CLI invocation of `convert_netcdf_to_cog.py` did not reach conversion because the current planner failed to resolve the selected filename; directly invoking the converter on the registered Mekong `uparea.nc` task passed full native-pixel verification under the 2024 environment. This is recorded as an existing CLI/planner issue outside this dependency task, not as a dependency failure.

Earlier checks on existing environments remain separately labeled: root `.venv` `pip check` passed; selected Explorer/GFM tests were 15 passed and one deselected; a broader selection reported 34 passed/3 failures caused by existing code/test/data assumptions. These modern-environment checks are not substituted for the historical-profile results above.

## Interpretation and limitations

2024 has focused evidence for common map, COG, plotting, metadata and tutorial NetCDF paths on this host. It does not prove cross-platform compatibility or justify lowering dependency minima. 2022 has useful core scientific-I/O and map-analysis evidence, but lacks full Rasterio installation and is outside today's Explorer's declared Panel/Bokeh range. The profiles remain historical experiments, not production locks. Automatic fallback remains unjustified.

The two compatibility gaps exposed in this experiment are platform/build constraints (Rasterio 1.3.4 on Apple Silicon) and the malformed version-name/metadata pairing in the historical lmoments3 artifact. The latter is handled with a content-hash-pinned PyPI file URL in the 2022 profile.
