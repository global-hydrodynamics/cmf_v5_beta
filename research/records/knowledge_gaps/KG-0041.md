# KG-0041 — Selecting a simulation subset of overland bifurcation layers

- **Gap ID:** KG-0041
- **Linked event ID(s):** EV-0825–EV-0827
- **Category:** model configuration / bifurcation interface
- **Evidence basis:** source-code inspection and maintainer task instruction
- **Status:** open

## What was unknown or assumed?

How should an experiment request fewer overland bifurcation layers than are available in the map parameter file, including requesting zero overland layers while retaining channel bifurcations? This is a v5 run-configuration question; the task explicitly says not to add a runtime setting without first establishing its location and compatibility contract.

## How was it discovered?

While mapping separate external `riv_width` and `ovl_width_N` fields into the model's existing channel-first array, source inspection found `NPTHLEV` is set directly from the number of layers in the input table. The model then allocates `PTH_WTH`, `PTH_ELV`, `PTH_MAN`, path-flow prognostics, Restart arrays and output records using `NPTHLEV`, and activates each positive-width layer during initialization. Relevant evidence is in `src_main/cmf_ctrl_maps_mod.F90` (`READ_BIFPARAM`, CSV/NetCDF readers and path-layer initialization), `src_main/yos_cmf_map.F90`, `src_main/cmf_ctrl_vars_mod.F90`, `src_main/cmf_ctrl_restart_mod.F90`, and `src_main/cmf_ctrl_output_mod.F90`. `NLFP` is used for floodplain terrain and flood-state layers; it was not found to be an independent bifurcation-layer selector.

## Verified facts

- File layer count and current model `NPTHLEV` are coupled: one channel layer plus every overland width layer in the file.
- Internal layer 1 is channel; internal layers 2 onward are overland.
- Positive width sets the corresponding pathway elevation/activation state for that internal layer.
- `NPTHLEV` dimensions affect pathway flow state, restart variables and `pthflw` output dimensions.
- No independent supported run setting for the requested overland subset was identified in the inspected source/configuration.
- `NLFP` describes floodplain vertical discretization and is not used as the count of stored overland bifurcation fields in the new readers.

## How was the knowledge formalized?

The bifurcation metadata specification and affected README documents describe file layers as channel plus overland-only layers and state that current runs use all file overland layers. The task note and [DR-0065](../discussions/DR-0065.md) record the future setting question and prohibit silently equating it with `NLFP`.

## Resolution trace

- Resolution method: source-code analysis and sample-contract review.
- Evidence or maintainer explanation: no runtime layer selector was specified; task scope required preserving current execution behavior.
- Final interpretation and rationale: keep the parameter-file count as current `NPTHLEV`; do not truncate or reinterpret layers during this format migration.
- Future proposal for maintainer review: define an independent requested overland count in the run configuration, bounded by `0..NOVERLAND_FILE`, with the backward-compatible default equal to all available layers. Specify whether unused widths remain in the path inventory with zeroed/inactive model layers or whether output/path dimensions shrink; then define Restart compatibility and `pthflw` reporting consistently.
- Human review: pending.

## Verification and limits

Reader mapping and compilation were checked, and sample widths were preserved. No full simulation or Restart compatibility test for a layer subset was run because no subset setting was introduced. Current behavior using every file layer remains.

## Why the gap matters

Users cannot currently select a lower overland bifurcation-layer count independently of the file. A future option affects which pathways are active and the dimensions and interpretation of Restart and `pthflw`; a casual `NLFP` alias or silent truncation could change model behavior.
