# KG-0040 — NetCDF mask semantics in subbasin equivalence

- Gap ID: `KG-0040`
- Linked event ID(s): `EV-0810`
- Category: NetCDF mask semantics / subbasin Fortran equivalence
- Evidence basis: source/test comparison; unresolved
- Status: open

## What was unknown or assumed?

Does the Python `analysis_subbasin.py` NetCDF path treat masked `uparea` values consistently with the established Fortran/Binary workflow when classifying or propagating terminal subbasins? The current comparison does not establish equivalence for the Mekong sample.

## How was it discovered?

While validating the `script_params/s05-subbasin.sh` sample after the workflow reorganization, the existing NetCDF-output digest did not match its Fortran/Binary reference. The mismatch is outside the changed Shell organization and was not modified. This matters because successful wrapper execution alone does not validate the numerical result.

## Verified facts

- With the single-stage threshold of 30,000 km², the NetCDF sample output SHA-256 was `46edbdb81f3a987cd5023d10a1503f4b7c6ae867c663a967bbecf4aabdc5aa08`; the existing Fortran/Binary reference SHA-256 is `4c5e85be796a3957fe67d3883ec8ad7cafd15689d1fc81ccf87ef4da0e4a7b1e`.
- In read-only comparison of the tracked Mekong products, `nextxy.nc` and `uparea.nc` raw numeric values equal their Binary counterparts. The NetCDF `uparea` variable presents 3,034 pixels as masked.
- No causal conclusion about the output difference has been established. Other validity/masking semantics and implementation behavior require focused review.

## How was the knowledge formalized?

The mismatch and limits are recorded in [VR-0251](../validation_runs/VR-0251.md) and retained as an explicit assertion in [`test_analysis_migration.py`](../../../map/tools/tests/test_analysis_migration.py). No source algorithm or map data was altered.

## Verification and limits

The output difference was reproduced in a temporary map copy. Raw NetCDF/Binary inputs were read without modifying source files. The analysis covered the Mekong sample and one threshold only; it does not determine global behavior or the correct scientific handling of masked cells.

## Why the gap matters

Users may choose the NetCDF-first map workflow while expecting results equivalent to the preserved Fortran/Binary implementation. The discrepancy must be understood before claiming such equivalence. It is non-blocking for grouping Shell inspection commands under `script_params`.
